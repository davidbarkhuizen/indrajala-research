# Registrations

The launch scripts of the probes and studies run by hand (2026-10-15 to 2026-10-23, before the batch
runner), kept **verbatim** for their headers: each holds a probe's registration (its population,
cell, feasibility and expectations, written before its data) or a probe's expectations. indrajala-ml's
workplans cite them, D63's and D67's by sha256 (`state-formation/probe-d63.sh` b32f5c2995709114...,
`state-formation/probe-d67.sh` 411f31578d966b10...), which these copies keep. They are records, not
tools: their paths (`~/code/wt-*`, `~/labour/`, process ids) are those of the time. Don't run them.

One folder per indrajala-ml workplan (most retired; their text is in indrajala-ml's history):

| folder | what |
| --- | --- |
| `state-formation/` | stages 4a-4a'''', option 1's panel, D32-D38, the core matrix (4b-core), D54-D67 |
| `commitment-control/` | the thermostat's two probes, annealing, the commitment never returning (its arms, harm check and scorecard) |
| `snap-wall/` | P1, the certificate guard, the stable-seed replay |
| `one-code-one-state/` | R1's probe, R3 and R4's probe |
| `window-branches/` | S5 with the branches at width 32 |
| `general-algebras/` | round 2 |
| `code-consolidation/` | P1, A with the certificate guard |

Moved here from indrajala-ml's `docs/probe-launches/` on 2026-10-29, where every hand-run launcher
was first archived (indrajala-ml #1071, #1073; that tree, at indrajala-ml 30122e8, also holds the
launchers whose registrations live in a PR or workplan, and the operational scripts: waits, queues,
stops and moves).
